## Critical learnings carried from Phases 1 and 2

- **memory_layer write path is fixed but historical data is not backfilled.** See Task 0. This is the single most important thing for Phase 3 ranking.
- **Two-copy duplication is real and load-bearing.** `src/service/PlanningService.ts` + `src/service/DocumentService.ts` + `src/service/EntityService.ts` + `src/service/RetrievalService.ts` are the production path; `src/domain/service.ts` (class `MemoryService`) is the legacy mirror the tests exercise. `src/persistence/d1/DocumentRepository.ts` (new) + `src/persistence/d1/repository.ts` (legacy `MemoryRepository`). Change both or tests/prod diverge.
- **The ranking core is `src/domain/ranking.ts`**: `rerankSearchHits` (filters superseded/archived + excludeLayers, then sorts by `computeRankingScore`) and `computeRankingScore` (the additive scoring you are replacing). It is called from `src/service/RetrievalService.ts` `searchMemoryBase` and the `deriveExcludeLayers` helper. `tests/unit/ranking.test.ts` is your TDD surface.
- **Superseded handling already works**: superseded docs are filtered by default and penalised `-0.25`; `include_superseded: true` surfaces them. Phase 2 added `record_decision` canonical-key auto-supersession and parked-deal entity states. Do not re-litigate this; build on it.
- **Session pack budget** is enforced by `enforceCompactSessionBudget` + the `compact*` helpers in `src/domain/session.ts`. Phase 2 added a `needs_review_tasks` field; the pack is currently `trimmed: true` at ~63KB. The 191-item alphabetical `current_context` manifest and repeated repo-coverage blocks are the main bloat.
- **Entity states** live in `entity_states` (D1) via `EntityRepository.upsertEntityState` (supersedes prior active on write) and are read by `listEntityStatesForEntities` (`includeSuperseded` supported). `resolve_current_truth` in `RetrievalService.ts` is where state-vs-retrieval authority (RC-6) must be wired.
- **No migrations were needed in Phase 2** and likely none in Phase 3 — the columns exist. If you add one, `deploy:production` applies remote D1 migrations.
